# Python 多重继承 + super() + **kwargs 笔记

## 1. super() 的本质
- `super()` 不是"调用父类"，而是"按 MRO 路线图，把参数交给下一站"。
- 下一站是谁，不看当前类自己继承了谁，而是看**最终实例对象的路线图**。
- 路线图 = `class Child(父类A, 父类B, ...)` 括号里的顺序，可用 `类.__mro__` 打印。

## 2. **kwargs 的两个身份（长得一样，作用相反）
| 位置 | 作用 | 通俗说法 |
|---|---|---|
| 函数定义里 `**kwargs` | 收集/打包 | 把别人多给的、我不要的，装进字典 |
| 函数调用里 `**kwargs` | 使用/拆包 | 把字典撕开，原样传给下一站 |

**一个装，一个倒。**

## 3. 链条上的两种角色
| 角色 | 例子 | 手里有袋子吗 | 怎么发参数 |
|---|---|---|---|
| **起点（发货人）** | Duck | 没有，它是第一个 | 直接点名写括号里发出去 |
| **中转站** | Swimmer / Flyer / Entity | 有上一站的袋子 | 拿走自己要的，剩下 `**kwargs` 转发 |

- 起点例：`super().__init__(name=name, swim_speed=..., fly_speed=...)`
- 中转站例：`super().__init__(**kwargs)`

## 4. 每个协作类的固定三步
1. 从参数里拿走自己要的那个；
2. 剩下的用 `**kwargs` 收进袋子；
3. `super().__init__(**kwargs)` 把袋子发给下一站。

一路传到 `object`（终点站，啥也不干），再原路返回贴属性。

## 5. 方法调用也是按 MRO 找
- `对象.方法()` 时，Python 沿 MRO 从前往后找，哪个类先定义了该方法就用哪个。
- 初始化时整条链都跑过，所有属性都挂在同一个 self 上，所以 Mixin 方法里能直接用别人贴的属性。

## 6. Mixin 模式
- 本体类（如 Entity）：管"我是谁、我在哪"。
- 能力类（如 Swimmer/Flyer）：只管加一种能力，不关心别的。
- 最后用 `class Duck(Swimmer, Flyer, Entity)` 拼装，加新能力 = 加一个类 + 括号里塞个名字。

## 7. 总结
> 定义时收，调用时发；super 负责按路线图交棒，**kwargs 负责路上不丢参数；起点直接点名发货，中转站用袋子转发。
